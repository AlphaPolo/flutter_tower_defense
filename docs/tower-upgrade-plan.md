# 塔升級系統 — 設計（Model A 線性 → **Model B 分支，已實作**）

> 目標：把每座塔的「招牌能力」抽成**升級後才有/才變強**。基礎塔**變弱但費用砍半**，
> 玩家用金幣逐級投資解鎖能力 → 形成「便宜鋪基礎 vs 集中培養主力」的策略。

---

## 0. 現況（Model B，已實作）

升級已從線性（Model A）演進成 **Model B 分支樹**：

```
        Lv1 基礎
          │
      ┌───┴───┐        ← Lv2 二擇一（選了就鎖）
     A         B
    ┌┴┐       ┌┴┐      ← Lv3 依 Lv2 結果各再二擇一
  A1  A2    B1  B2
```

- 每塔 6 個升級節點、**4 種最終 build**、最高 3 級。兩個分岔點（Lv2、Lv3）。
- **資料驅動**：升級樹 = `kTowerUpgradeTree`（`lib/game/tower_type.dart`），每個
  `TowerUpgradeNode` 帶 `mods`（有效數值覆寫）；塔的 getter 用 `mod('key', base)` 讀，
  數字全集中在樹裡（**確切數值以該檔為準**，本文件不重複列以免走鐘）。
- 塔狀態：`TowerComponent.chosen`（已選節點）→ `level = 1 + chosen.length`、`_mods` 疊加
  （葉覆寫分支覆寫基礎）。選項/購買：`upgradeOptions` / `upgradeTower(node)`
  （`lib/game/tower_defense_game.dart`）。UI：`_upgradeControl` 並排兩張選項卡。
- 各塔分支主軸：冰凍(減速/範圍)、火焰(傷害/射程)、風刃(轉速/範圍)、
  雷電(連鎖/麻痺)、火炮(範圍/中心加成)、毒(固定毒傷/%血量)、滾木(傷害/發射頻率)。
- 「選了就鎖」＝選過的階不能改；要另一種 build 就再蓋一座。

以下第 1–5 節為 **Model A 的原始規劃（歷史紀錄）**，數值多已被上面的樹取代。

## 3. 架構

### 3.1 塔的「有效數值」
塔改為讀 **有效數值 = 基礎 + 已購升級**，不再直接讀 `kTowerStats` 的固定值。
- `TowerComponent` 加 `int level`（1~3）與 `int spentOnUpgrades`（拆除退款用）。
- 目前寫死的常數要移成**依 level 計算的 getter**，例如：
  - 雷電：`int get chainLimit => level >= 3 ? 5 : (level >= 2 ? 3 : 1);`
    - 麻痺**每級都有、逐級加強**：如 `paralyzeChance`(Lv1 0.1 → Lv3 0.5)、
      `paralyzeMs`(Lv1 120 → Lv3 500)；Lv1 就會偶爾、極短暫地定住敵人。
  - 火炮：`double get blastHex => level >= 2 ? 1.9 : 1.2;`、`bool get centerBonus => level >= 3;`
  - 毒/火焰/風刃/冰凍/滾木 同理各自的關鍵參數。
- 共用的 `damage`/`range` 若要隨級成長，也走同一套 getter（base × 級數係數 或各塔明列）。

### 3.2 升級資料表（給 UI / 費用 / 說明）
效果邏輯放各塔（因每塔差異大、難全資料化），但**費用與說明**用資料表統一：
```dart
class TowerUpgrade { final String name; final int cost; final String desc; }
// 每塔 Lv2、Lv3 的 (名稱, 費用, 說明)
const Map<TowerType, List<TowerUpgrade>> kTowerUpgrades = { ... };
```

### 3.3 升級動作
`game.upgradeTower(point)`：若有下一級且金幣足夠 → 扣費、`tower.level++`、`spentOnUpgrades += cost`。

### 3.4 UI（沿用點塔的資訊面板）
- 顯示「等級 X/3」。
- 若非滿級：顯示**下一級名稱 + 效果 + 費用**與**升級鈕**（金幣不足則 disabled）。
- 塔上加**等級小圓點**（1~3 顆）標示等級。
- **拆除退款**：改為 50% ×（基礎費 + 已投入升級費）。

### 3.5 經濟
- Lv1 基礎費 = 現有費用 ÷ 2（見第 2 節）。
- 升級費見第 2 節（之後再抓平衡）。

## 4. 分階段實作
1. **地基**：`TowerComponent.level` + `spentOnUpgrades` + 有效數值 getter 化（先把雷電做通，驗證流程）。

3. **逐塔套用**：把 7 座塔的關鍵常數改成依 level，並把基礎費砍半、基礎能力削弱。
4. 平衡微調（先不強求）。

每階段照慣例：`flutter analyze` → build → 部署 staging 驗證 → commit。
